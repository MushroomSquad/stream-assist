# Бэклог

## Точка входа для отладки (ИИ и человек)

- Файл логов в `<app_data_dir>/logs/`: подключения Twitch/Spotify/OBS, выкупы и их исходы,
  ошибки озвучки и синтеза. Без токенов и ключей.
- `GET /debug` на локальном axum-сервере: JSON-снимок состояния (текущий трек, очередь,
  `TtsView`, виджеты, статусы подключений, последние предупреждения). Без секретов.
- Кнопка «Открыть папку логов» в настройках.

## Клонирование голоса на GPU

Сейчас клон и синтез идут только на CPU (`Device::Cpu` в `voice_lab/worker.rs`),
клон «точно» — 25+ минут.

- `supertonic3-tts` умеет `Device::Gpu`/`Auto` при фиче `cuda` (→ `ort/cuda`).
- Выбор «CPU / GPU (NVIDIA)» в разделе «Записи» для клонирования; синтез для эфира
  оставить на CPU (GPU занят игрой и энкодером OBS).
- Риски: сборка ONNX Runtime с CUDA заметно тяжелее; у пользователя нужны CUDA 12 и cuDNN 9.
  Вариант — GPU-провайдер как отдельный скачиваемый пакет (как пакет тренажёра),
  а в AppImage оставить CPU-сборку.
- Если GPU не инициализировался — понятная ошибка, не тихий откат на CPU.

## Прогресс установки пакета обучения

`uv sync` (~7 ГБ: torch, CUDA-библиотеки) шлёт прогресс только `venv 0/1` → `1/1`,
поэтому полоска стоит на нуле все минуты скачивания. stdout uv выкинут, stderr — в
`trainer/install.log`.

- Прогресс по `install.log`: число строк `Downloaded X` / `Downloading X` → `venv n/m`,
  плюс имя текущего пакета.
- Показывать в панели хвост `install.log` при ошибке.
- Повторная установка после обрыва докачивает из `trainer/uv-cache`.

Python-окружение уже изолировано: свой `.venv`, свой CPython от uv
(`UV_PYTHON_PREFERENCE=only-managed`), кеш внутри папки приложения; системный pip не трогается.
