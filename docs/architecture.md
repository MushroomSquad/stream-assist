# Stream Assist — архитектура

Документ для разработчиков. Исходные требования — в
[спецификации](superpowers/specs/2026-11-02-stream-assist-design.md),
пошаговый план v1 — в [плане](superpowers/plans/2026-11-02-stream-assist-v1.md).

## Общая схема

```
Twitch EventSub ─┐                     ┌─► Spotify Web API
Панель (Tauri) ──┼─► driver (tokio) ───┼─► Twitch Helix (статусы, чат, награда)
Виджет (WS) ─────┘      │    ▲         ├─► YouTube oEmbed / Data API
                        ▼    │         └─► OBS WebSocket
                   Player::step (чистый автомат)
                        │
                       SQLite (очередь, история, настройки)
```

- **Tauri v2**, ядро на Rust (tokio), панель на SvelteKit (SPA, adapter-static).
- Локальный **axum**-сервер на `127.0.0.1:<port>` отдаёт виджет, `sdk.js`, темы,
  WebSocket и OAuth-callback Spotify.
- Вся логика очереди и сторожа — **чистый автомат** `Player::step(input, now) -> Vec<Action>`
  без async и сети. Им единолично владеет драйвер.

## Voice Lab

Voice Lab хранит свою SQLite-БД `voice-lab.db` и файлы в `<app_data_dir>/voice-lab/`.
Музыкальная БД и автомат очереди независимы от студии голоса.
В P0 ONNX работает на CPU в одноразовом процессе `stream-assist --vl-worker <request.json>`.
Родитель обменивается с воркером JSONL; EOF stdin завершает воркер при выходе приложения.
Отмена клона убивает процесс; профиль появляется только после проверки результата.
Runner допускает один клон и один синтез одновременно; повтор того же вида возвращает `JOB_BUSY`.
P1 добавляет независимый `TrainRunner`: один Python-процесс обучения на NVIDIA GPU,
без блокировки CPU-клона и синтеза. `trainer.rs` устанавливает закреплённое окружение
через внешний uv и проверенные SHA-256 веса WavLM в `trainer/`. Встроенный адаптер
`resources/trainer/train_job.py` обучает только `style_ttl`; исходник тренажёра скопирован
под MIT. Python запускается без shell, с `-I`, офлайн-окружением и отдельной группой
процессов; stdout — JSONL, stderr — `training/<id>/worker.log`.
EOF stdin сохраняет состояние и завершает обучение; остановка имеет таймаут 30 с
до kill группы процессов. Новый Store переводит `running` в `interrupted`, resume
загружает атомарно сохранённый `state.pt`. Чекпоинты и итог валидируются и становятся
неизменяемыми профилями `origin=train`. Миграции Voice Lab последовательны через
`PRAGMA user_version`; версия 2 добавляет `training_runs`. Лок Store не держится через await.
Установка/удаление пакета и активное обучение взаимно исключены.
Эксперименты (P2): `vl_explore` строит веса (интерполяция A→B или Дирихле с seed через
ChaCha8) и запускает одну операцию воркера `SynthBatch`, которая занимает слот синтеза и
отменяется через `vl_cancel_job`; готовые элементы регистрируются как рендеры после выхода
воркера при любом исходе. Сходство с записью — косинус эмбеддингов speaker encoder (CPU).
`project.rs` пишет и читает `.svlab` (ZIP, только Stored/Deflate): имена записей не
становятся путями, лимиты считаются по распакованным байтам, всё проверяется до применения.
Руководство и результаты приёмки — в [voice-lab.md](voice-lab.md).

## Озвучка стрима

`tts/` содержит фильтры, гейт чата, очередь в памяти и отдельный async-движок.
Драйвер маршрутизирует TTS-награду и события чата через unbounded-канал `TtsMsg`,
читает исходы погашений отдельным каналом и отменяет неизвестные погашения при reconcile.
`Played`/`Skipped` выполняют награду, остальные исходы возвращают баллы.
Движок синтезирует через `Runner::synth_file` в `voice-lab/tmp/tts/<id>.wav`,
без регистрации рендеров и заданий Voice Lab. Слот синтеза общий с Voice Lab;
`JOB_BUSY` повторяется раз в секунду до 60 секунд. `/widget/tts` получает только
`TtsPlay`/`TtsStop`/`Reload` через роль WS `tts` (одно активное подключение),
читает `/tts/<id>.wav` без кеша и подтверждает окончание или ошибку.
После завершения WAV удаляется; страховка воспроизведения — длительность + 10 секунд.
Повторное подключение виджета во время воспроизведения снова шлёт `TtsPlay` текущего
элемента и перезапускает страховку. Движок помнит до 500 обработанных погашений
(`seen`): повторная доставка EventSub и гонка с reconcile не дают двойного исхода.

EventSub подписывается на погашения и на `channel.chat.message` при каждом welcome;
сбой подписки на чат (403 → `tts_chat_relogin`, прочее → `tts_chat_failed`) не рвёт
сессию. Битое сообщение чата и неизвестные уведомления игнорируются, битое погашение
по-прежнему рвёт сессию (переподключение → reconcile). Источник сообщения проверяет `rules::route_chat`; роли, кулдауны и фильтры проверяет движок.
Награды принадлежат триггерам `Settings.rules`; они активны только при включённых
триггере и действии. Драйвер передаёт движку сматченный текст чата и флаг активности
наградного триггера. Выключение сохраняет очередь, новые неактивные выкупы возвращаются.
Панель получает `TtsView` командой `tts_state` и событием `tts`; предупреждения озвучки
не попадают в музыкальный `WidgetState.warning`. Музыкальный автомат независим.

### Жизненный цикл наград и миграция

При подключении `Lifecycle` планирует поиск известных наград и ленивое создание:
только активный наградный триггер без id может создать награду. `ensuring` учитывает
создание в полёте: повторное сохранение не запускает второй POST, после ответа
применяется актуальное состояние. Результат создания для уже удалённого триггера
переносится в `retiring`. Ошибки доступны через `rule_errors` по id триггера.

Удалённые награды хранятся в персистентном `Rules.retiring`. Не начатые элементы
локально снимаются с возвратом, текущий элемент передаётся в `keep`.
`retire_reward` выполняет строго: выключить → отменить все `UNFULFILLED`, кроме `keep`
→ DELETE. Только успешное удаление убирает запись из `retiring`; офлайн и ошибки
оставляют её для повтора при следующем подключении. При выходе и `TwitchLogout`
все `rules.reward_ids()` (включая `retiring`) ставятся на паузу параллельно с бюджетом 2 с.

Старый JSON сохраняется без изменений под ключом `settings_legacy`, затем
мигрируется в `Settings.rules` и пересохраняется. Сохраняются существующие `reward_id`,
метки и лимиты; откат на старую версию не поддерживается. Id триггеров не переиспользуются:
их выдаёт персистентный `Rules.next_id`. Панель принимает результат `save_settings`,
чтобы сохранить назначенные id, и не перечитывает форму при событиях `rule_errors`.

## Ключевые инварианты

1. **Баллы возвращаются только до старта трека.** Все отмены идут через
   `Player::cancel`, который ничего не делает для `item.started == true`.
2. **FULFILLED — только после подтверждённого старта**: успешный `PlayResult`
   (Spotify) или `Yt Started` (YouTube).
3. **На каждый `SpotifyPlay` драйвер возвращает ровно один `PlayResult`,
   на каждый `ResolveFallback` — ровно один `FallbackResolved`**, даже при ошибке
   или таймауте. У автомата нет своих таймаутов на эти ответы.
4. **Порядок исполнения пачки действий**: локальные отметки в БД
   (`mark_cancelled`, `history_push`) → `Persist` (снимок очереди) → сетевые вызовы.
5. **Новый выкуп**: `insert_item` (уникальность по `redemption_id`) →
   `Player::step(Enqueue)` → действия. Нельзя сохранять снимок до того, как элемент
   попал в автомат, — `save_state` удалит строку.
6. Опрос Spotify — не больше одного в полёте; ответ, отправленный до последнего
   `SpotifyPlay`, отбрасывается.
7. Правила по снимку Spotify (конец трека, ручная пауза, чужой трек) работают только
   для Spotify-трека. Пока активен фолбэк, драйвер не пытается запускать Spotify.
8. Лок `Db` (`std::sync::Mutex`) никогда не держится через `.await`.

## Сторож

| Наблюдение | Решение |
|---|---|
| Наш URI, пауза, прогресс у конца (или сброс в 0 после конца) | Конец трека → следующий |
| Наш URI, пауза, прогресс далеко от конца | Ручная пауза → ничего не делать |
| Чужой URI вне 4 с после старта, не у конца | Стример взял управление → `Suspended` |
| Чужой URI / нет плеера у конца трека | Автоплей/конец → следующий |
| Устройство пропало | Повтор play с позиции, бэкофф 2–30 с |
| API недоступен ≥ 30 с и прошёл ожидаемый конец (или трек ещё не стартовал) | Фолбэк на YouTube |
| YouTube не стартовал за 20 с | Отмена (до старта — с возвратом) |
| YouTube не прислал конец к `duration + 10 с` (без пауз) | Считаем концом |

## Выкупы и сверка (reconcile)

- EventSub WebSocket: подписка только на свежей сессии; `session_reconnect` — без
  переподписки; жёсткий обрыв — переподключение с бэкоффом, подписка и `Resync`.
- При старте и на `Resync` драйвер читает все `UNFULFILLED` выкупы награды:
  `Queued` → пропустить, `Started` → FULFILLED, `Cancelled` → отменить повторно,
  `Unknown` → обработать как новый.
- Дубли отсекаются по `redemption_id` (in-flight множество + уникальный индекс в БД).

## Виджет

- `GET /widget/music?part=now|queue&scale=N` — HTML активной темы.
- `GET /widget/sdk.js` — клиент: WebSocket `/ws`, события для темы, YouTube IFrame Player.
- WebSocket принимает только `Origin`/`Host` `127.0.0.1|localhost:<port>`.
- YouTube-команды получает одно соединение `role=player` — его запрашивает только
  страница внутри OBS (`window.obsstudio`) и только для `part=now|all`.
  Новое player-соединение вытесняет старое (код `4001`) и получает повтор текущего трека.
- Контракт тем — [themes.md](themes.md).

## Как добавить вид триггера или действие

1. Добавить вариант `TriggerKind` или `ActionKind` в `rules.rs`, параметры и валидацию.
2. Добавить допустимое сочетание в `allowed` и соответствующий `allowedTriggers` панели.
3. Добавить ветку маршрутизации в `route_reward` или `route_chat`.
4. Реализовать исполнение действия в драйвере; для наград использовать общий
   `Lifecycle` и операции `RewardOp`, сохраняя инварианты автомата и возвратов.
5. Обновить TS-типы и настройки панели. Тексты чата — в `i18n.rs`, панели — в `ru.ts`.

```sh
npm ci
cd src-tauri && cargo build --examples && cargo test  # ~380 тестов: автомат, БД, клиенты (wiremock), сервер, Voice Lab, озвучка
npm run check                     # svelte-check
TWITCH_CLIENT_ID=… npm run tauri dev

```

Демо виджета без аккаунтов: `THEME=phantom PART=now PORT=47899 cargo run --example widget_demo`
(в `src-tauri`), затем открыть `http://127.0.0.1:47899/widget/music`.

## Известные ограничения v1

- Текущий элемент удаляемой награды (трек или фраза озвучки) остаётся `UNFULFILLED`
  до конца и становится `FULFILLED` при DELETE награды на Twitch. Если он затем
  не запустится или не синтезируется, возврата баллов не будет.

- Spotify в режиме разработчика: каждый стример создаёт своё приложение.
- Отдельного бот-аккаунта нет — бот пишет от аккаунта стримера.
- Смена порта применяется после перезапуска.
- Интерфейс только на русском (строки вынесены в `ru.ts` и `i18n.rs`).
