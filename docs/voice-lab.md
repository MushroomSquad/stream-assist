# Voice Lab

Вкладка «Голоса» — локальная студия Supertonic 3: клонирование из записи,
импорт профилей, смешивание и синтез речи. CPU-путь работает без CUDA и Python;
на Linux x86_64 клонирование также доступно на NVIDIA GPU.
Любой профиль можно выбрать голосом [озвучки стрима](user-guide.md#озвучка);
озвучка делит с панелью слот синтеза, поэтому рендер во время озвучки может ответить «занято».

## Установка

Откройте «Голоса» и установите модель (~400 МБ). Можно также скачать speaker encoder:
он необязателен, но рекомендуется для качества клонирования. Нужна сеть до окончания
установки; затем записи, профили и синтез обрабатываются локально.
Загрузчик проверяет SHA-256 файлов закреплённой ревизии
`3cadd1ee6394adea1bd021217a0e650ede09a323`; повторная установка пропускает корректные файлы.

Для MP3, FLAC, OGG и M4A установите системный `ffmpeg`. Без него доступен импорт WAV.
При сборке на Linux нужны ALSA (`libasound2-dev` / `alsa-lib-devel`) и зависимости Tauri;
при первой сборке `ort` скачивает ONNX Runtime из сети.

## Запись и клонирование

1. Во вкладке «Записи» импортируйте аудио и подтвердите право использовать запись для создания голоса.
2. Выделите 5–15 секунд чистой речи одного человека без музыки, шума и длинных пауз.
   Допустимый регион — 1–15 секунд. Исходный файл ограничен 250 МБ и 30 минутами;
   рабочая копия преобразуется в WAV mono s16 44100 Гц, оригинал сохраняется отдельно.
3. Укажите язык записи и точный транскрипт выделенного региона. Для русского транскрипт
   обязателен; для английского и языков со встроенным банком проб допускается пустой.
4. Задайте имя, пресет, seed (по умолчанию 42) и нажмите «Клонировать».
   Прогресс показывает стадию, итерации и loss. «Отменить» завершает процесс без создания профиля.

| Пресет | Итерации mix / row / refinement | Качество проб |
|---|---|---|
| Быстро | 10 / 15 / 25 | 5 |
| Стандарт | 20 / 30 / 50 | 8 |
| Точно | 40 / 60 / 100 | 8 |

Клонирование заметно нагружает CPU и занимает минуты: не клонируйте во время эфира.
Одновременно разрешены один клон и один синтез; второй запрос того же вида получает `JOB_BUSY`.
Более долгий пресет не гарантирует лучшее сходство. Профиль содержит стиль общей модели,
а не отдельную обученную модель; оцените результат прослушиванием.

## Клонирование на видеокарте

На Linux x86_64 в «Записях» установите GPU-пакет (≈230 МБ), затем выберите
«Устройство → Видеокарта (NVIDIA)». Нужны драйвер NVIDIA 580+, CUDA 13,
cuDNN 9 и не менее 600 МБ свободного места для установки. Пакет хранится в
`<app_data_dir>/voice-lab/gpu/`; доступны прогресс, отмена и удаление.
Выбор устройства запоминается. На остальных платформах используется процессор.

Отсутствующие библиотеки перечисляются в панели. Повреждённый пакет нужно
переустановить; запуск вернёт `GPU_PACK_INVALID`. При `GPU_FAILED` проверьте
драйвер и библиотеки, затем [логи](debugging.md), включая `gpu/worker.log`.
Раздел с `noexec` на `/home` мешает загрузке провайдера из папки приложения.

Установка и удаление GPU-пакета
запрещены во время GPU-клона; CPU-клон этому не мешает.
Синтез в Voice Lab и озвучка стрима продолжают работать на CPU.
Клонирование занимает минуты; во время эфира не запускайте.

Приёмка 2026-11-04 (RTX 5070 Ti, драйвер 615, CUDA 13.4, cuDNN 9):

- клон «быстро» на GPU вместе с проверкой — ≈2 мин (на CPU тот же пресет 3–5 мин);
  «точно» на GPU не замерялся;
- синтез фразы: GPU ≈70 мс (первый вызов 1–8 с — разогрев), CPU ≈2 с;
- синтез стохастический: сходство (косинус speaker embedding) двух CPU-прогонов
  одного стиля 0,88–0,90, пары CPU↔GPU 0,83–0,92. Тест `real_gpu_clone_fast`
  требует CPU↔GPU ≥ 0,75 и не хуже CPU↔CPU − 0,10, длину WAV ±5%;
- сборка в podman Ubuntu 24.04: GLIBC_2.39, CUDA нет в NEEDED, CPU-синтез работает;
- AppImage 191,1 МБ (было 190,7 МБ): GPU-провайдер в сборку не входит.

## Голоса, микшер и рендеры

Обучение удалено из приложения: оставшиеся профили «Обучение» работают как обычные,
лишние чекпоинты удаляйте во вкладке «Голоса». Папки `trainer/` и `training/` можно удалить вручную.

В «Голоса» доступны встроенные M1–M5/F1–F5, клоны и импорт style JSON Supertonic 3.
Импорт проверяет форму тензоров и конечность значений, ограничен 2 МБ.
Можно переименовывать и тегировать профили. Удаление своего профиля удаляет его рендеры;
встроенные профили удалить нельзя.

В «Микшер» добавьте до восьми разных профилей и задайте веса 0–100: сумма должна быть
положительной. Доли нормируются автоматически; для трёх голосов можно начать с 55/30/15.
TTL смешивается с сохранением средней нормы строк. Стратегия DP управляет длительностями:

- `dominant` — DP участника с наибольшим весом; при равенстве выбирается первый;
- `weighted` — смешивание DP, экспериментальный режим;
- `select` — DP выбранного участника микса.

Ctrl+Z / Ctrl+Shift+Z отменяют и возвращают изменения микшера. Укажите текст (1–1000 символов),
язык, скорость 0,7–1,5 и качество 5–12; генерация запускается кнопкой.
«Сохранить снимок» создаёт профиль микса с рецептом и исходными весами.
Превью само по себе профиль не сохраняет. Совпадающий профиль не дублируется.

«Рендеры» позволяет слушать WAV, ставить ★ и сравнивать два варианта A/B;
выбор победителя отмечает его избранным. RTF — время синтеза / длительность аудио,
без загрузки модели. Хранятся 200 последних неизбранных рендеров и все избранные.
Синтез недетерминирован: два запуска одной фразы могут различаться.

## Эксперименты

Вкладка «Исследование» — экспериментальный способ подбирать голоса. Для пачки
задайте одну фразу (1–300 символов), язык, скорость 0,7–1,5 и качество 5–12.

- «Интерполяция»: два разных профиля A/B и 3–9 точек. `t` — вес B в смеси:
  при `t=0` звучит A, при `t=1` — B. Это вес микшера, а не доля пути между
  голосами: из-за нормировки строк изменения могут сгущаться в середине.
  Длительности DP всегда смешиваются как `weighted`.
- «Случайные смеси»: 2–8 профилей, 2–8 вариантов, seed от 0 до 4294967295.
  Доступны DP `dominant` и `weighted`. При одинаковых профилях, их порядке,
  seed и стратегии повторяются веса и стиль; звук не повторяется побитово,
  поскольку синтез использует случайный шум без seed.
- «Сравнить с записью»: выберите источник с подтверждённым правом использования
  и регион 1–60 секунд. Нужен установленный speaker encoder. Косинус сходства
  позволяет отсортировать карточки; это подсказка для прослушивания, а не
  оценка качества или доказательство личности говорящего.

«Сохранить снимком» сохраняет стиль и рецепт выбранной смеси в библиотеку.
У крайних точек интерполяции этой кнопки нет: это исходные профили A/B.
«Отменить» останавливает пачку; готовые рендеры остаются с подписью
«Отменено, показаны готовые». Пачка занимает слот синтеза; таймаут —
300 + 60 × число элементов секунд. После перезапуска рендеры и рецепты доступны
в «Рендерах», а подписи и сортировка ленты не сохраняются.

«Экспорт проекта» создаёт `.svlab` — ZIP с `manifest.json`, всеми своими
профилями (без встроенных) и избранными WAV. Сохраняются рецепты и теги;
исходные записи и модель в архив не входят. В новом каталоге данных сначала
установите или скопируйте модель, затем выберите «Импорт проекта».
Отчёт покажет число профилей, рендеров, пропусков и другую ревизию модели.

Ограничения архива: манифест ≤ 1 МиБ, профиль ≤ 2 МиБ, WAV ≤ 50 МиБ,
суммарно распакованных данных ≤ 500 МиБ, файл архива ≤ 500 МиБ,
не более 2000 ZIP-записей; записи только без сжатия или Deflate, другие методы отклоняются. Имена файлов профилей —
`profiles/<64 строчных hex-символа>.json`, рендеров — `renders/<1–9 цифр>.wav`.
Имя профиля ≤ 200 символов, до 20 тегов по ≤ 50 символов; WAV — mono PCM16,
8–48 кГц. Перед применением проверяются содержимое, хеши и лимиты.

Профили с уже известным SHA-256 пропускаются, локальные имена и теги сохраняются.
Новые профили получают происхождение `import`, рендеры — отметку избранного.
Рендеры при повторном импорте дублируются. Ошибка проверки ничего не применяет;
ошибка ввода-вывода на этапе применения может оставить частичный импорт.

## Экспорт и перенос

Экспортируйте профиль как `final_voice.json`: это чистый style JSON без metadata,
записи и рецепта. Рецепт микса экспортируется отдельно и содержит SHA-256 входных профилей
и веса; он не заменяет сам профиль. Рендер экспортируется как WAV.

В новом каталоге данных установите модель (или скопируйте `voice-lab/models/`),
импортируйте `final_voice.json` через «Голоса» и запустите синтез. Исходные записи и
профили участников микса для этого не нужны.

## Где лежат данные

Корень — `<app_data_dir>/voice-lab/` (Linux обычно `~/.local/share/app.streamassist/voice-lab/`;
`XDG_DATA_HOME` меняет базовый каталог). Внутри:

- `voice-lab.db` — отдельная SQLite-БД источников, профилей, рендеров;
- `models/supertonic-3/<revision>/`, `models/speaker-encoder/` — модель и encoder;
- `sources/original/`, `sources/work/` — оригиналы и рабочие WAV;
- `profiles/`, `renders/` — канонические JSON и WAV;
- `tmp/` — временные файлы, очищаются при открытии хранилища.

Для резервной копии закройте приложение и скопируйте весь каталог. Воркеры завершаются
при закрытии stdin родителем, поэтому после выхода приложения клон не продолжает работу.
Записи, транскрипты и тензоры не отправляются в сеть и не записываются в логи.

## Лицензии и использование

Веса Supertonic 3 распространяются по [OpenRAIL-M](https://huggingface.co/Supertone/supertonic-3/blob/3cadd1ee6394adea1bd021217a0e650ede09a323/LICENSE),
код `supertonic3-tts` — MIT, speaker encoder 3D-Speaker — Apache-2.0.
LICENSE модели Supertonic сохраняется вместе с файлами. Соблюдайте условия соответствующих лицензий.
Используйте только записи, на которые у вас есть право. Запрещено обманное использование:
не выдавайте синтез за подлинную речь человека без его согласия.

## Приёмка экспериментов P2

`acceptance_p2` — ignored Rust-тест командных helpers `explore`, `save_snapshot`
и `render`, используемых Tauri-командами. Требуются реальные модель, encoder
`speaker_encoder.onnx`, `luna_reference.wav` и `nora_reference.wav` в
`SUPERTONIC_MODEL_DIR`. Из `src-tauri`:

```sh
CARGO_PROFILE_RELEASE_PANIC=unwind cargo build --release --bin stream-assist
CARGO_PROFILE_RELEASE_PANIC=unwind \
SUPERTONIC_MODEL_DIR=/path/to/model-cache \
cargo test --release --lib acceptance_p2 -- --ignored --nocapture
```

Бинарник предварительно собирается потому, что тест внутри библиотеки вызывает
настоящий дочерний процесс `stream-assist --vl-worker`. Модель и encoder копируются
в каждый временный каталог данных; исходный кеш не меняется.

Сценарий: английские Luna/Nora → два CPU-клона `fast`, seed 42 с encoder →
русская фраза, интерполяция 5 точек по порядку с DP `weighted` → снимок t=0.25 →
две пачки по 4 случайных смеси от трёх профилей с seed 7 и равными весами в
рецептах → `explore` с регионом источника, конечное сходство у каждого элемента
и сортировка → отмена после второго `Item`, сохранение готовых рендеров →
экспорт `.svlab` → импорт в новую БД с копией модели → профили, рецепты, теги,
избранный WAV после `prune_renders(0)` → синтез импортированным снимком.
Проверяются непустой звук и очистка временных файлов. Сортировка здесь выполняется
над результатом Rust API; UI-сортировка и субъективное сходство требуют ручной проверки.

Ручная приёмка в `npm run tauri dev` остаётся **pending для пользователя**:

- Отменить пачку на середине: готовые карточки остаются с подписью
  «Отменено, показаны готовые»; следующая генерация доступна.
- У крайних точек нет «Сохранить снимком», у t=0.25 кнопка сохраняет профиль.
- Сравнить с записью, отсортировать карточки по сходству и прослушать;
  проверить экспорт/импорт проекта через диалоги.
