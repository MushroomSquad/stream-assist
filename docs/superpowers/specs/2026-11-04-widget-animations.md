# Анимации виджетов «Сейчас играет» и «Очередь»

Статус: черновик · 2026-11-04

## Зачем

Все шесть встроенных тем музыкального виджета статичны: смена трека, новый заказ
и сдвиг очереди происходят мгновенно, прогресс прыгает раз в 2,5 с. Нужны анимации
в стиле каждой темы, которые хорошо читаются на стриме и не мешают.

## Ограничения

- Только встроенные темы `src-tauri/assets/widget/themes/{underground,glass,crt,block,phantom,moonlight}`
  и `src-tauri/assets/widget/sdk.js`. Виджет озвучки (`tts.html`) без изменений.
- Без новых зависимостей, без внешних запросов, только CSS-анимации и небольшой JS.
  Окружение — браузерный источник OBS (CEF/Chromium); анимировать `transform`, `opacity`,
  `filter`, `clip-path`, `background-position` (без layout-свойств в циклах).
- Состояние приходит при событиях и раз в `POLL_MS = 2500` мс; каждое состояние темы
  перерисовывают (`replaceChildren`). Анимация не должна повторяться от обычного
  обновления состояния: только при реальном событии.
- Совместимость: существующие пользовательские темы работают без изменений;
  новое в SDK — только дополнения.
- `prefers-reduced-motion: reduce` отключает все анимации тем (контент сразу в конечном
  состоянии), скрытие виджета без задержки.
- Данные по-прежнему только через `textContent`.

## События, которые анимируются

| Событие | Как определить | Анимация |
| --- | --- | --- |
| Появление виджета | `visible` false→true или первая загрузка | вход панели (стиль темы) |
| Скрытие виджета | `visible` true→false | выход панели ≤ 400 мс, затем `hidden` |
| Смена трека | `now.id` изменился (включая null→трек) | вход блока трека: обложка, название, исполнитель, заказчик с небольшой задержкой между ними |
| Нет трека | `now` стал null | блок трека скрывается (как сейчас) |
| Новый трек в очереди | `id` элемента не было в прошлой очереди | вход строки |
| Строки, оставшиеся в очереди | `id` был раньше | без повторной анимации; сдвиг вверх — плавно (FLIP по `id`, ≤ 300 мс) |
| Счётчик очереди | число изменилось | короткий «щелчок» счётчика |
| Прогресс | каждое состояние | плавное движение между опросами; при смене трека — сразу в 0 без «отката» |
| Воспроизведение / пауза | `state.mode` | фоновые циклы (вращение диска, мерцание и т. п.) идут только в `Playing` |

Первая отрисовка после загрузки страницы анимирует вход панели и строк очереди
(с нарастающей задержкой строк, не более 5 × 60 мс).

## Стиль по темам

- **underground** (стрит, лайм, диск): диск-обложка вращается как пластинка в `Playing`
  (8 с на оборот), при смене трека диск «вкатывается», плашка выезжает из-под диска;
  новая строка очереди въезжает справа с лаймовой вспышкой фона; счётчик подпрыгивает.
- **glass** (матовое стекло): появление из размытия (`blur` + лёгкий масштаб), мягкая
  смена обложки, по полосе прогресса проходит блик; строка «Далее» — подъём с затуханием.
- **crt** (терминал): включение кинескопа (сжатие по вертикали → полный кадр со вспышкой
  яркости), название печатается (посимвольно, `steps`), курсор `_` в строке времени мигает,
  в `Playing` медленно бегут строки развёртки и лёгкое мерцание; новые строки очереди печатаются.
- **block** (стикеры): элементы «шлёпаются» с перелётом и доворотом (название, затем
  исполнитель и заказчик), обложка выскакивает с поворотом; «NEXT ▸» въезжает жёстко слева.
- **phantom** (буквы-вырезки, красная вспышка): буквы названия появляются по одной
  с поворотом и масштабом, сохраняя свой случайный наклон; красная вспышка вращается
  при смене трека и медленно «дышит» в `Playing`; обложка влетает с поворотом;
  строки очереди врезаются справа со скосом.
- **moonlight** (синий скос, циан): по панели проходит световая полоса при смене трека,
  обложка выезжает со скосом, надпись MUSIC на фоне медленно дрейфует в `Playing`,
  точка прогресса пульсирует свечением; строки очереди выезжают слева по очереди.

Длительности входа 250–700 мс, задержка между элементами 40–120 мс. Циклы — без
резких вспышек (не чаще 3 раз в секунду, без полноэкранного мигания).

## SDK (дополнения, документируются в docs/themes.md)

- Перед вызовом обработчиков SDK выставляет `document.documentElement.dataset.mode =
  state.mode` (`Idle`, `Starting`, `Playing`, `Paused`, `Suspended`), чтобы CSS включал
  циклы через `html[data-mode="Playing"]`.
- `StreamAssist.replay(element, className)` — перезапустить CSS-анимацию класса.
- `StreamAssist.show(element, visible)` — показать сразу; при скрытии добавить класс
  `sa-leaving`, дождаться окончания его анимации на самом элементе (не дольше 400 мс), затем
  `hidden = true`. Повторный показ во время выхода отменяет скрытие. Без анимации выхода — скрыть сразу.
- `StreamAssist.progress(element, percent, trackId)` — ширина полосы с плавным ходом
  (`transition: width` — разрешённое исключение из правила про layout) и мгновенным сбросом
  при смене трека, откате или первой отрисовке.
- `StreamAssist.list(container, items, keyOf, build)` — список по ключам: существующие строки
  переиспользуются (их анимации не обрываются опросом), новые получают класс `sa-enter`,
  сдвинувшиеся плавно доезжают (FLIP).
- Раздел в docs/themes.md помечается как экспериментальный на один выпуск.

## Проверка

- `src-tauri/tests/widget_sdk.mjs`: тесты `dataset.mode`, `replay`, `show` (повторный показ
  во время выхода, всплывший `animationend`, reduced motion), `progress`, `list`.
- `examples/widget_demo.rs`: режим `DEMO=cycle` — смена трека каждые 8 с, добавление и
  удаление элементов очереди, пауза/воспроизведение, скрытие/показ, чтобы смотреть анимации
  в браузере и OBS.
- Скриншоты headless Chromium каждой темы в частях `all`, `now`, `queue` в середине и после
  анимации: конечное состояние совпадает с текущей вёрсткой (без смещений и обрезки).
- Ручная проверка пользователем в OBS.
