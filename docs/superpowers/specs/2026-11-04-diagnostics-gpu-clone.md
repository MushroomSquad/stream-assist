# Отладка, клонирование на GPU, прогресс установки тренажёра — спецификация

Статус: реализовано; ручная release/AppImage-приёмка и замеры клонирования — за оркестратором. Ветка `feat/diag-gpu-progress`. Выполненные пункты удалены из бэклога.

## Зачем

1. Сейчас у приложения нет логов (около 12 `eprintln!`). Если что-то ломается в AppImage,
   ни человеку, ни ИИ не на что опереться, кроме скриншотов.
2. Клонирование голоса идёт только на CPU, режим «точно» — 25+ минут.
3. Установка пакета тренажёра (`uv sync`, ~7 ГБ) показывает только `venv 0/1`, поэтому
   полоска стоит на нуле все минуты скачивания и выглядит как зависание.

## A. Отладка

### A1. Файл логов

- Путь: `<app_data_dir>/logs/stream-assist.log` (Linux: `~/.local/share/app.streamassist/logs/`).
- Формат строки: `<UTC ISO-8601 с миллисекундами> <область> <сообщение>\n`,
  области: `app`, `twitch`, `spotify`, `obs`, `music`, `tts`, `vl`, `train`, `server`, `panic`.
- Ротация: при превышении 5 МБ файл переименовывается в `stream-assist.log.1`
  (старый `.1` удаляется), пишется новый. Итого ≤ 10 МБ.
- Каждая строка также уходит в stderr (как сейчас `eprintln!`).
- Ошибка записи логов никогда не роняет и не блокирует приложение.
- Хук паники пишет `panic` с сообщением и местом (профиль release — `panic = "abort"`).
- Никаких секретов: токены, ключи, `client_secret`, коды OAuth и тексты сообщений
  чата в лог не попадают. Для чата и наград пишутся id, логин зрителя и длина текста.
- Что логируется (минимум):
  - старт: версия, порт сервера, путь к данным;
  - Twitch: welcome/подписки (успех/403/ошибка), разрыв и переподключение, reconcile;
  - Spotify и OBS: ошибки запросов (код/вид ошибки, без тел ответов с токенами);
  - музыка и озвучка: получен выкуп (id, награда), исход (FULFILLED/CANCELED и причина);
  - озвучка: постановка в очередь, ошибка синтеза, старт/конец/таймаут воспроизведения,
    подключение/отключение виджета;
  - Voice Lab: старт/исход задания (вид, код ошибки), падение воркера;
  - тренажёр: этапы установки и их исход;
  - все существующие `eprintln!` переводятся на логгер.
- Воркер Voice Lab (отдельный процесс) логов сам не пишет; родитель пишет код ошибки.

### A2. `GET /debug`

- На существующем локальном axum-сервере. Та же проверка `Host`, что у `/ws`
  (`127.0.0.1:<port>` или `localhost:<port>`), иначе 403. `Origin` не требуется.
- Ответ — JSON (`Cache-Control: no-store`):

```json
{
  "version": "0.1.0", "port": 47800, "uptimeS": 1234, "dataDir": "…",
  "logFile": "…/logs/stream-assist.log",
  "widget": { /* WidgetState */ },
  "tts": { /* TtsView или null, если движок ещё не запущен */ },
  "twitch": true,
  "spotify": { /* SpotifyStatus */ },
  "logTail": ["последние 200 строк лога"]
}
```

- Отказ (403), если `Sec-Fetch-Site` есть и не `none` (страницы тем того же origin).
- `tts` — без текстов: элементы очереди как `id/источник/логин/длина`.
- `spotify` — только флаг подключения, без запроса к API.
- Каждая часть собирается с таймаутом 2 с; не ответившая часть становится `null`,
  ответ всё равно отдаётся.
- Секретов в ответе нет (те же правила, что для лога; `Settings` целиком не отдаётся).

### A3. Панель и документация

- В «Подключениях» (вкладки «Настройки» нет) блок «Отладка»: путь к логам, кнопка «Открыть папку логов»
  (через уже подключённый `tauri-plugin-opener`)
  и строка с адресом `http://127.0.0.1:<порт>/debug`, кнопка «Копировать».
- `docs/debugging.md` — короткая инструкция для человека и ИИ: где лог, как
  `tail`/`grep`, как `curl /debug`, где лог установки тренажёра и обучения.
  Ссылки из README и `docs/architecture.md`.

## B. Клонирование на GPU (NVIDIA)

### Проверено прототипом (2026-11-04, RTX 5070 Ti, драйвер 615, CUDA 13.4, cuDNN 9)

- `supertonic3-tts` с фичей `cuda` → `ort-sys` берёт сборку pyke `ms@1.28.0`
  `cuda13,tensorrt,nvrtx`: ядро ORT по-прежнему статически в бинаре, CPU-путь не меняется.
- CUDA-провайдер грузится отдельной `.so` из `dirname(argv[0])`. Запуск с
  `argv[0] = <dir>/stream-assist` (`exec -a`, `Command::arg0`; символьная ссылка тоже работает)
  заставляет ORT искать провайдеры в `<dir>`. `LD_LIBRARY_PATH` и `dlopen` заранее не работают.
- Бинарь с фичей `cuda` не имеет CUDA в `NEEDED` — без NVIDIA приложение стартует как раньше.
- Провайдер из сборки pyke не содержит ядер для sm_120 (`cudaErrorNoKernelImageForDevice`).
  Официальный `onnxruntime-linux-x64-gpu_cuda13-1.28.0.tgz` от Microsoft содержит
  sm_75…sm_120 + PTX и работает с ядром pyke той же версии 1.28.0.
- Синтез фразы: CPU ≈ 2 с, GPU ≈ 70 мс (первый вызов ≈ 1–8 с разогрева).

### Поведение

- Сборка: фича `cuda` у `supertonic3-tts` только для `cfg(all(linux, x86_64))`; Windows/macOS без изменений; `ORT_CUDA_VERSION=13`. Версия ORT
  провайдера (1.28.0) жёстко связана с `ort =2.0.0-rc.13` — комментарий в `Cargo.toml`.
- **GPU-пакет** (только Linux x86_64; на других платформах опции нет):
  - скачивается по кнопке из
    `https://github.com/microsoft/onnxruntime/releases/download/v1.28.0/onnxruntime-linux-x64-gpu_cuda13-1.28.0.tgz`,
    SHA-256 `84d28f27589090b280d4312743efd3d450cd4ac7d1e1d75e7d9076d9637bf9de`, ~229 МБ;
  - из архива извлекаются только `lib/libonnxruntime_providers_cuda.so`,
    `lib/libonnxruntime_providers_shared.so`, `LICENSE`, `ThirdPartyNotices.txt`
    в `<app_data>/voice-lab/gpu/`; нужно ≥ 600 МБ свободного места;
    распаковка системным `tar` с явными именами членов во временный каталог,
    затем атомарное переименование; архив удаляется;
  - SHA-256 извлечённых файлов закреплены в коде и проверяются при установке и
    при проверке статуса (`pack: none | ok | broken`);
  - прогресс скачивания и отмена — как у загрузки модели; кнопка «Удалить GPU-пакет»;
  - установка и удаление запрещены во время клонирования на GPU (удалять `.so` под CPU-клоном безопасно);
  - статус показывает недостающие системные библиотеки CUDA (`ldd` провайдера).
- **Запуск**: клон с `device = gpu` запускает тот же исполняемый файл с
  `argv[0] = <app_data>/voice-lab/gpu/stream-assist` (файла по этому пути нет);
  stderr воркера пишется в `gpu/worker.log`. Воркер грузит TTS и speaker encoder с
  `Device::Gpu`. Синтез (Voice Lab, эксперименты, озвучка стрима) всегда на CPU.
- **Ошибки**: если GPU не инициализировался, вернул ошибку или воркер упал во время
  клона — задание завершается с кодом `GPU_FAILED`, без тихого отката на CPU. В лог
  пишется текст ошибки ORT или хвост `gpu/worker.log`. В meta профиля — устройство. Текст в панели: «Не удалось запустить на видеокарте. Нужны драйвер
  NVIDIA 580+, CUDA 13 и cuDNN 9. Подробности — в логе».
- **Взаимоисключение**: один клон за раз (как сейчас). Клон на GPU запрещён, пока
  идёт обучение (`JOB_BUSY`), и наоборот, обучение не стартует во время GPU-клона.
- **Панель «Записи»**: выбор «Процессор / Видеокарта (NVIDIA)» рядом с пресетом.
  Видеокарта недоступна, пока пакет не `ok`; рядом — «Установить GPU-пакет (≈230 МБ)»
  с прогрессом. Выбор запоминается в `localStorage`. Подсказка о времени — своя для GPU
  (значение после замера в приёмке). Предупреждение «во время эфира не запускайте»
  остаётся для обоих.
- Статус: `vl_gpu_status() -> { supported, pack, installing, gpu: {name, driver} | null, missingLibs: string[] }`;
  `gpu` берётся тем же `nvidia-smi`, что у тренажёра.

## C. Прогресс установки тренажёра

- Пока идёт `uv sync` (с `NO_COLOR=1 --color never`), родитель раз в 500 мс читает
  `trainer/install.log` и считает **в байтах**: `total` — сумма размеров из строк
  `Downloading <имя> … (<размер>)`, `done` — сумма размеров скачанных (` Downloaded <имя>`);
  имя — первый токен.
  Событие `vl-train-install` получает стадию `packages` с `done/total` и `item` —
  имя последнего начатого и ещё не скачанного пакета.
- Когда все начатые скачаны, а `uv` ещё работает, — стадия `venv` (распаковка/установка),
  полоска без значения (indeterminate).
- Если `uv` завершился с ошибкой, команда возвращает `TRAINER_INSTALL_FAILED`, а
  панель показывает последние 20 строк `install.log` (новая команда
  `vl_train_install_log() -> String`, ≤ 8 КБ хвоста).
- В панели подпись: «Установка прерывается при закрытии программы; повтор докачает
  из кеша». Повтор уже работает через `trainer/uv-cache` — проверить, что он не
  чистится при ошибке.
- Python-окружение остаётся изолированным (`.venv`, CPython от uv, кеш в папке
  приложения), системный pip не используется — отметить в user-guide.

## Приёмка

- `cargo test`, `cargo clippy --all-targets`, `npm run check`, JS-тесты — зелёные.
- Ручная: лог появляется и ротируется; `curl http://127.0.0.1:<port>/debug` отдаёт JSON
  без секретов; GPU-пакет ставится, клон «точно» на GPU завершается и даёт профиль,
  время записано в `docs/voice-lab.md`; без пакета — `GPU_PACK_MISSING`, с повреждённым — `GPU_PACK_INVALID`, без CUDA — `GPU_FAILED` с понятным текстом;
  установка тренажёра показывает рост `n/m` и имя пакета.
- Сборка в контейнере `ubuntu:24.04`: glibc ≤ 2.39, без CUDA в `NEEDED`, CPU-синтез работает.
- Синтез стилем GPU-клона на GPU и CPU даёт близкий голос (сходство CPU↔GPU ≥ 0.75 и не ниже двух CPU-прогонов минус 0.10, длина ±5%).
- Размер AppImage до/после.
