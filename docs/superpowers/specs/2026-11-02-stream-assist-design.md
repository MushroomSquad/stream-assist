# Stream Assist — дизайн v1 (музыка по наградам)

Дата: 2026-11-02

## Зачем

Стример хочет, чтобы зрители заказывали музыку за баллы канала Twitch, а заказы
играли через его Spotify, шли по очереди и показывались на стриме в виджете OBS.
Программа будет раздаваться другим стримерам, поэтому вход в сервисы должен быть
простым, без ручной возни с токенами.

Музыка — первая из многих наград. Основа должна позволять добавлять новые
реакции на награды без переписывания существующего.

## Цели v1

1. Награда «Заказать трек»: зритель вводит название или ссылку → трек в очередь.
2. Очередь пуста → трек играет сразу и появляется плашка в виджете.
   Очередь не пуста → трек встаёт в конец.
3. Очередь закончилась → тишина, виджет прячется. Свой плейлист не включаем.
4. Воспроизведение через Spotify стримера. Ссылки YouTube, которых нет в Spotify, играют через YouTube.
5. Виджет OBS с текущим треком и очередью. Темы на выбор плюс загрузка своих.
6. Панель управления: пропустить, удалить из очереди, поменять порядок, пауза.
   Лимиты для зрителей настраиваются в панели.
7. Удобная авторизация Twitch и Spotify для любого стримера.
8. Надёжность: музыка не должна останавливаться из-за сбоев Spotify.

## Не цели v1

- Другие награды (только расширяемая основа под них).
- Чат YouTube и стриминг на YouTube. В v1 YouTube — только источник музыки.
- Свой плейлист «по умолчанию» при пустой очереди.
- Автообновление программы.

## Анти-цели (провал, даже если «работает»)

- **Музыка остановилась посреди стрима из-за Spotify** — главный страх стримера.
- Стример вручную копирует токены или правит конфиги, чтобы залогиниться.
- Сторож включает музыку обратно, когда стример сам поставил паузу.

## Решения стримера

- Spotify — основной источник, YouTube — запасной для ссылок.
- Всё работает на том же компьютере, что и стрим.
- Tauri (переносимость, один бинарник). Раздаём другим стримерам.
- Пустая очередь → тишина.
- Автовозврат баллов, если трек не найден или удалён стримером.
- Лимиты настраиваются в панели.
- Темы виджета: **A «Underground»** по умолчанию (утверждена по макету
  `.superpowers/brainstorm/*/content/ug2-theme-v2.html`), а также **B Glass**,
  **C Terminal/CRT**, **D Block** (`widget-themes.html`, кроме карточки A).
  Плюс загрузка кастомных тем.
- В кружке темы A — обложка трека (Spotify — обложка альбома, YouTube — превью
  видео в круге, нет картинки → заглушка темы).
- Панель управления — спокойный обычный UI, не в стиле UG2.

### Тема A «Underground» — суть стиля

Тёмные полупрозрачные панели (~70% чёрного), тонкая салатовая рамка (`#c6f27a`),
узкий жирный курсив (Barlow Condensed Italic или аналог), салатовые акценты,
строки через одну темнее. Плашка трека в духе всплывашки EA Trax: круглая обложка
слева, три строки (исполнитель, «название», «Заказал: ник»), светлый вертикальный
язычок справа с надписью MUSIC, выезд слева. Очередь — табличка с салатовой
градиентной шапкой. **Без логотипов и названий EA/NFS.**

## Как сделано (решения ассистента, стример их не утверждал по отдельности)

### Стек

- **Tauri v2.** Ядро на Rust (tokio).
- **Локальный HTTP/WS-сервер (axum)** внутри приложения на `127.0.0.1`, порт
  настраивается. Через него OBS получает виджет, а авторизация возвращается на localhost.
- **Панель** — Svelte + Vite внутри окна Tauri.
- **Хранилище** — SQLite (очередь, настройки, история). Очередь переживает
  перезапуск программы.
- **Секреты** (refresh-токены) — системное хранилище ключей (crate `keyring`).
- Rust-крейты: `twitch_api` (Helix + EventSub), `rspotify` или прямые HTTP-вызовы,
  `obws` (obs-websocket v5).

### Расширяемость

Внутри ядра есть шина событий (`tokio::sync::broadcast`). Интеграции публикуют
события (`RedemptionAdded`, `PlayerStateChanged`, …), а функции подписываются на
них. Функция — модуль, который реализует трейт с методами `on_event` и
`routes`/`settings`. Музыка — первая такая функция, следующие награды
добавляются новыми модулями. Каждая награда в настройках привязана к функции.

### Twitch

- Вход через **Device Code Flow** (публичный клиент, без секрета). Client ID
  приложения зашит в сборку.
- Scopes: `channel:read:redemptions`, `channel:manage:redemptions`,
  `user:read:chat`, `user:write:chat`.
- **Программа сама создаёт награду «Заказать трек»** через Helix. Twitch
  разрешает менять статус выкупа (FULFILLED / CANCELED с возвратом) только для
  наград, созданных тем же Client ID. Стоимость, название и кулдаун награды
  настраиваются в панели.
- События — через EventSub WebSocket, `channel.channel_points_custom_reward_redemption.add`.
- Во всех релизах один официальный Client ID (решение ассистента). Если
  сохранённая награда создана другим Client ID (форк, своя сборка),
  программа это замечает и создаёт награду заново.
- Программа закрывается → награда ставится на паузу. При запуске
  разбираются выкупы в статусе UNFULFILLED, пришедшие, пока программа не работала.
- Бот отвечает в чат от аккаунта стримера: «трек добавлен, позиция N» / «не
  найдено, баллы возвращены». Отдельный бот-аккаунт — позже.

### Spotify

- Вход через **Authorization Code + PKCE**, редирект на `http://127.0.0.1:<port>/callback/spotify`.
- Из-за ограничений режима разработчика Spotify каждый стример **создаёт своё
  приложение в Spotify Dashboard** и вставляет Client ID. В панели для этого
  есть пошаговый мастер с указанием, какой Redirect URI вставить.
- Нужен **Spotify Premium** (управление воспроизведением). Мастер проверяет
  это и прямо говорит, если Premium нет.
- Scopes: `user-read-playback-state`, `user-modify-playback-state`, `user-read-currently-playing`.
- **Очередь своя, не очередь Spotify** (у Spotify нельзя удалять и
  переставлять). Следующий трек запускается через `PUT /me/player/play` с
  `uris`, когда текущий заканчивается.

### Разбор заказа

- Ссылка `open.spotify.com/track/…` или `spotify:track:…` → берём напрямую.
- Ссылка YouTube → сначала пытаемся найти тот же трек в Spotify по названию
  видео. Нашли с уверенным совпадением → играем Spotify, иначе → играем YouTube.
- Текст → поиск в Spotify, берём первый результат, прошедший лимиты.
- Не нашли → отклонить выкуп (баллы вернутся) и написать в чат.

### YouTube-воспроизведение

- Играет в виджете OBS через IFrame Player API. Звук идёт через Browser
  Source OBS, поэтому в мастере есть подсказка включить мониторинг источника,
  иначе стример сам этот трек не услышит.
- Пока играет YouTube-трек, Spotify стоит на паузе. Сторож считает эту паузу
  нашей, а не ручной.

### Очередь и воспроизведение

Состояния: `Idle` (тишина) → `Playing(item)` ↔ `Paused(manual)`.
- Новый заказ в `Idle` → сразу играть. Иначе → в конец.
- Трек доиграл → следующий, либо `Idle`, и виджет прячется.
- **Возврат баллов (решение стримера): после начала воспроизведения баллы
  не возвращаются никогда.** Трек начал играть → выкуп FULFILLED сразу, даже
  если его потом пропустили или он сломался. CANCELED с возвратом бывает
  только до старта: трек не найден, нарушен лимит, стример удалил заказ из
  очереди, YouTube-видео не встраивается или не загрузилось.
- Панель: пропустить, удалить, перетащить, пауза/продолжить, громкость Spotify.

### Лимиты (настраиваются в панели)

Макс. длительность трека; запрет повторов (тот же трек в очереди или среди
последних N сыгранных); макс. заказов от одного зрителя в очереди; запрет
explicit; чёрный список исполнителей/треков. Нарушение → отклонить с
возвратом и сообщением в чат.

YouTube-заказы без API-ключа (решение ассистента): название берём через
oEmbed, длину проверяем в плеере виджета при загрузке, до старта. Слишком
длинный трек пропускается с возвратом баллов. Флаг explicit для YouTube не
проверяется.

### Сторож (главная анти-цель)

- Каждые 2–3 с опрашиваем `GET /me/player`.
- Токен обновляется заранее, за 5 минут до истечения.
- **Различаем ручную паузу и сбой.** Если устройство то же, трек наш и
  `is_playing=false`, а мы паузу не ставили, — это ручная пауза: панель
  показывает «пауза», сторож ничего не делает.
- **Трек в Spotify сменился без нас (решение стримера: вариант «а»)** —
  стример взял управление на себя. Очередь заказов встаёт на паузу
  (`Paused(manual)`), в панели появляется кнопка «Вернуть очередь». Сторож
  не вмешивается. Текущий заказ при этом засчитывается (FULFILLED).
- **Сбой** — устройство пропало или пришли ошибки API/сети. Тогда повторы с
  backoff, перевод воспроизведения на последнее известное устройство,
  продолжение с сохранённой позиции.
- **Фолбэк на YouTube (решение ассистента).** При падении API локальный
  клиент Spotify обычно продолжает играть, поэтому замену не включаем сразу.
  Условие: API недоступен **и** прошло ожидаемое время конца текущего трека
  (по последнему известному прогрессу). Тогда в панели заметное
  предупреждение, а следующие треки ищутся на YouTube по «исполнитель —
  название» и играют в виджете. Для поиска нужен YouTube Data API key,
  стример указывает его по желанию. Без ключа — только предупреждение и
  повторы. Мастер просит выключить «Автовоспроизведение» в Spotify, чтобы
  локальный клиент не продолжил играть сам.
- Spotify вернулся → следующий трек снова идёт через Spotify.

### OBS

- Подключение к obs-websocket v5 (по умолчанию `localhost:4455` + пароль).
- В v1: кнопка «Добавить виджет в текущую сцену» создаёт Browser Source с
  правильным URL и размером. Индикатор подключения.
- Без OBS программа работает: виджет можно добавить вручную по URL.

### Виджет и темы

- URL: `http://127.0.0.1:<port>/widget/music`. Тема берётся из настроек и
  переключается из панели без правки OBS.
- Тема — это папка: `theme.json` (имя, автор, размер по умолчанию) + `index.html`/CSS/JS.
- Тема подключает `/widget/sdk.js`, который держит WebSocket к ядру и
  отдаёт события: `nowPlaying`, `queue`, `progress`, `hidden`. Это и есть
  контракт для кастомных тем, его надо коротко описать в документации.
- Встроенные темы зашиты в бинарник. Кастомные лежат в папке данных
  приложения (`themes/`), панель умеет импортировать .zip.
- Есть тестовый режим: панель шлёт фейковый трек, чтобы настроить виджет без заказов.

### Панель управления

Спокойный обычный UI, светлая/тёмная тема. Разделы: Сейчас + очередь (основной
экран), Награды, Лимиты, Виджет/темы, Подключения (Twitch, Spotify, OBS,
YouTube-ключ, статусы). Язык интерфейса — русский, строки вынесены в один файл,
чтобы позже добавить английский.

### Сборка и раздача

Сборки Windows / Linux / macOS через `tauri build` (CI позже). Twitch Client
ID задаётся при сборке.
