# Правила «триггер → действие» и редизайн панели

Статус: дизайн, 2026-11-03. Один план, две фазы в строгом порядке: сначала правила (ядро + API),
потом редизайн всей панели, включая экран правил.

## Зачем

Сейчас цепочка «вид триггера → конкретный триггер → действие» нигде не выражена явно.
`router.rs` сравнивает `reward_id` с двумя захардкоженными id, метка `%` живёт внутри
`TtsSettings.marker`, драйвер шлёт весь чат прямо в движок озвучки, настройки музыкальной
награды лежат в корне `Settings`. Стример хочет сам собирать в панели: выбрать вид триггера,
конкретный триггер и действие. Дальше каждый из трёх уровней будет расширяться
(новые виды триггеров, новые действия), поэтому вертикаль должна быть явной в модели,
в маршрутизации и в UI.

Панель сейчас выглядит «стрёмно» (слова пользователя): пользователь хочет полный редизайн,
красивый и удобный, с навыком `unslop` (`~/.claude/skills/unslop`).

## Цели

1. Явная модель: **действие** (по одному на вид) со своими настройками и лимитами и
   **списком триггеров**; каждый триггер = вид + конкретные параметры.
2. Вся маршрутизация событий Twitch (выкуп, сообщение чата) идёт через одну функцию,
   которая по правилам возвращает действие и данные для него.
3. Существующие настройки и уже созданные на Twitch награды переносятся без потерь:
   после обновления у стримера те же награды (те же `reward_id`), та же метка, те же лимиты.
4. Новые виды триггеров и действий добавляются вариантом enum + веткой в маршрутизации +
   записью в таблицу допустимых сочетаний, без переделки остального.
5. Полный редизайн панели по `unslop`: все вкладки, единая система токенов, новый экран правил.

## Не цели

- Новые виды триггеров или действий (например, заказ музыки из чата бесплатно).
- Несколько экземпляров одного действия (две «Озвучки» с разными голосами).
- Изменения автомата музыки (`player.rs`), движка озвучки сверх смены входа, Voice Lab-логики.
- Редизайн тем виджета OBS (`server/themes`, `assets/widget/*`) — это оверлеи стрима со своим
  контрактом тем (`docs/themes.md`). *Моё решение; пользователь может расширить.*
- Локализация: интерфейс остаётся только на русском.

## Анти-цели (провал, даже если «работает»)

- Дубли наград на Twitch после обновления или после смены настроек.
- Нарушение инвариантов из `docs/architecture.md` (баллы возвращаются только до старта,
  FULFILLED только после старта, reconcile).
- Музыкальная очередь или озвучка перестали работать у стримера, который просто обновился
  и ничего не трогал.
- Редизайн, который выглядит как очередной шаблон: фиолетовые градиенты, свечения, эмодзи
  в подписях (критерии — `unslop/references/signs.md`).

## Решения пользователя

- В панели — список правил, стример сам собирает: вид триггера → конкретный триггер → действие.
- Функционально — те же две вещи (музыка за баллы, озвучка), «только с нормальной реализацией».
- **Одно действие каждого вида**, у него один набор настроек и лимитов. К действию можно
  привязать **несколько триггеров**.
- **Награды обходят лимиты действия.** Лимиты действия (роли, кулдауны) применяются только
  к триггерам из чата. (Музыкальные лимиты — длительность, повторы, квота в очереди, explicit,
  блоклист — это правила допуска трека, а не «лимиты частоты»; они как и сейчас действуют на
  каждый заказ музыки. Сейчас у музыки есть только наградный триггер, вопрос не возникает.)
- Панель разрешает **только работающие сочетания**: Музыка ← Награда; Озвучка ← Награда,
  Метка в чате. Модель должна позволять добавить сочетание позже без переделки.
- Порядок: фаза 1 — правила в ядре и API, панель минимально подключается к новой форме
  настроек; фаза 2 — редизайн, экран правил рисуется сразу в новом стиле.
- Процесс: единый план → критик + архитектор до консенсуса → верификатор → исполнение
  задачами через `omc ask codex`, ревью по задачам — субагенты Claude.

## Модель (фаза 1)

Форма — ориентир, точные имена на усмотрение исполнителя:

```
Settings {
  rules: Rules,            // новое
  port, active_theme, youtube_api_key, obs, spotify_client_id,   // как было
  // reward_title, reward_cost, reward_cooldown_s, music_reward_id, limits, tts — уходят в rules
}
Rules { music: Action<MusicCfg>, tts: Action<TtsCfg> }
Action<C> { enabled: bool, cfg: C, triggers: Vec<Trigger> }
MusicCfg { limits: Limits }
TtsCfg  { profile_id, lang, speed, roles, global_cooldown_s, user_cooldown_s,
          strip_links, stop_words }
Trigger { id: String /* локальный, стабильный */, enabled: bool, kind: TriggerKind }
TriggerKind::Reward     { title, cost, cooldown_s, reward_id: Option<String> }
TriggerKind::ChatMarker { marker }
ActionKind { Music, Tts }   // + allowed(ActionKind) -> &[TriggerKindTag]
```

Правила:
- `reward_id` принадлежит приложению: как сейчас `keep_reward_id`, панель не может его
  подменить; при сохранении id сохраняются по `Trigger.id`.
- Метки уникальны среди всех триггеров; названия наград уникальны (так требует и Twitch).
  Метка — как сейчас: 1–3 непробельных символа, озвучивается текст **до** метки
  (`filter::extract_marked`, правило про цифру перед меткой сохраняется).
- Недопустимое сочетание, дубль метки/названия → ошибка валидации при сохранении (ядро
  проверяет само, панель лишь подсказывает).
- Триггер работает, только если включены и он, и его действие.

## Маршрутизация (фаза 1)

Одна чистая функция (развитие `router.rs`), примерно:
- выкуп: `reward_id` → `(ActionKind, trigger_id)` или `None`;
- сообщение чата: перебирает включённые `ChatMarker`-триггеры включённых действий и
  возвращает `(ActionKind, trigger_id, извлечённый текст)` для первого совпадения, иначе `None`.

Драйвер больше не шлёт весь чат в движок озвучки: он вызывает маршрутизацию и шлёт движку
только совпавшие сообщения уже с текстом. Проверка «сообщение из своего канала»
(`source_broadcaster_id`) — часть маршрутизации; роли и кулдауны остаются частью действия
«Озвучка» для чатовых триггеров (в движке). Награды по-прежнему обходят
роли и кулдауны.

## Жизненный цикл наград (фаза 1)

Обобщение текущей логики с двух наград на N наградных триггеров:
- при подключении: для каждого наградного триггера, у которого уже есть `reward_id`, найти
  награду (`find_manageable_reward` по id, затем по названию — как сейчас) и выставить
  `is_enabled` по «триггер включён И действие включено». Награда **создаётся лениво** —
  только когда триггер впервые оказывается включённым (при подключении или при сохранении),
  как сейчас у озвучки. Выключенный триггер без `reward_id` на Twitch ничего не создаёт:
  стример, который ничего не трогал, не увидит новых наград. *Моё решение;*
- при сохранении: патч только изменённых наград (как `tts_reward_patch`);
- новый наградный триггер — создать награду; **удалённый** — отменить с возвратом
  его ещё не начатые выкупы (для музыки через `Player::cancel`, т.е. не стартовавшие;
  для озвучки — не озвученные), затем удалить награду на Twitch (новый вызов Helix DELETE).
  *Моё решение;* награда сначала выключается, удаляемый id хранится персистентно
  (`retiring`) до успешного удаления — сбой или отсутствие подключения не теряют его,
  удаление повторяется при следующем подключении; ошибка показывается на карточке действия;
- **выключение** триггера или действия (решение пользователя): награда на Twitch получает
  `is_enabled:false`, новые выкупы не приходят; уже стоящие в очереди элементы
  **доигрываются / доозвучиваются** без возврата. Выкуп, пришедший по выключенному триггеру
  (гонка с Twitch, reconcile), отменяется с возвратом — как сейчас `Outcome::Disabled`.
  Для музыки это новое поведение (раньше музыку выключить было нельзя);
- выход приложения и `TwitchLogout` — пауза всех наград параллельно (бюджет 2 с, как сейчас);
- reconcile/`Resync` — по всем наградным триггерам каждого действия, а не по двум id.

Предупреждения/ошибки по наградам — по триггеру, чтобы панель могла показать их у строки.

## Миграция (фаза 1)

Старые настройки читаются и переводятся в `rules` при загрузке (serde-default + явная
функция миграции с тестами):
- Музыка: `limits` → `rules.music.cfg.limits`; `reward_title/cost/cooldown_s/music_reward_id` →
  один наградный триггер, `enabled: true`.
- Озвучка: `tts.reward_title/cost/cooldown/reward_id` → наградный триггер с
  `enabled = tts.reward_enabled`; `tts.marker` → триггер-метка с `enabled = tts.chat_enabled`;
  остальное → `TtsCfg`; `rules.tts.enabled = true` (включённость — на триггерах).
- Пустой/новый конфиг → по умолчанию: Музыка ← Награда «Заказать трек» 500;
  Озвучка ← Награда «Озвучить текст» 300 (выкл) и Метка `%` (выкл) — как текущие дефолты.
- После миграции сохраняется уже новая форма. Откат на старую версию приложения не
  поддерживается. *Моё решение.*

## API панели (фаза 1)

- `Settings` в TS отражает новую форму; команды `get_settings`/`save_settings` (или как они
  называются сейчас) работают с ней.
- Текущие вкладки «Награды», «Лимиты», «Озвучка» в фазе 1 правятся **минимально** — только
  чтобы приложение между фазами работало с новой формой (пути к полям, `npm run check`).
  В фазе 2 они исчезают (раскладка A), поэтому никаких улучшений UI в них в фазе 1 не делать.
  Добавление/удаление триггеров в UI — в фазе 2.
- `TtsView`, событие `tts`, очередь озвучки — без изменений по смыслу.

## Фаза 2: редизайн

- Инструмент — навык `unslop`; работа строго по его порядку: аудит → направление →
  проходы (spacing, color, icons, copy, type, layout, details, visuals, motion).
- **Контрольная точка:** аудит и направление (характер, мир, палитра, шрифт, сигнатурная
  деталь) показываются пользователю и утверждаются **до** правок экранов (через
  визуальный компаньон или скриншоты). Без утверждения проходы не начинаются.
- Объём: вся панель — навигация, «Сейчас», экран правил с настройками действий
  (заменяет «Награды», «Лимиты», настройки на «Озвучке»), очередь и тест озвучки, «Виджет»,
  «Подключения», Voice Lab со всеми подвкладками.
- Экран правил: вид триггера → конкретный триггер → действие; добавление/правка/удаление/
  включение триггеров, только допустимые сочетания, ошибки валидации и ошибки наград у строки.
  Раскладка **A** (решение пользователя): вкладка «Правила» — по карточке на действие
  («Заказ трека», «Озвучка»); в карточке переключатель действия, список триггеров
  (вид + параметры, вкл/выкл, правка, удаление, ошибка награды у строки), «+ триггер»
  (сначала вид — только допустимые для этого действия, потом параметры) и раскрываемые
  «Настройки и лимиты» действия. Вкладки «Награды», «Лимиты» и настройки на «Озвучке»
  исчезают. Очередь, URL виджета и тест озвучки — в карточке «Озвучка» или на «Сейчас»,
  на усмотрение исполнителя в рамках направления. Итоговые вкладки:
  Сейчас · Правила · Виджет · Подключения · Voice Lab.
- Стек: Svelte 5 + обычный CSS, как сейчас; новые UI-библиотеки не добавлять. Токены
  (цвета, отступы, типографика) — CSS-переменные в одном месте. Шрифты — **локально в
  бандле** (приложение работает офлайн и в Tauri), без Google Fonts по сети. *Моё решение.*
- Тёмная тема по умолчанию (стримеры работают рядом с OBS); светлая — на усмотрение
  исполнителя. *Моё решение.*
- Логика панели и команды Tauri в фазе 2 не меняются, кроме нужного для экрана правил.
- Доступность: фокус с клавиатуры, подписи у полей, контраст — не хуже текущего.
