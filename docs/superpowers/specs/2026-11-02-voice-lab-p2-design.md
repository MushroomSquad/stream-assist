# Voice Lab — P2: Experimental Voice Design (минимальный объём)

Дата: 2026-11-02
Источник: SVL-SPEC-001 §2 P2, §9, фаза 5. Опирается на P0 (`2026-11-02-voice-lab-design.md`).
От P1 не зависит: БД и формат рецепта не меняются.

## Зачем

Когда базовые профили есть, хочется исследовать пространство голосов: плавно перейти от A к B,
получить случайные смеси нескольких голосов, отсортировать результаты по похожести на нужную
запись и перенести удачные голоса на другой компьютер. Всё помечено «экспериментально».

## Объём P2

1. **Интерполяция A→B.** 2 профиля, N = 3–9 точек, вес B = `100·i/(N−1)`, вес A = остаток;
   `style_dp` всегда `weighted` (иначе длительности прыгают в середине). Одна фраза → пачка рендеров
   лентой. `t` — вес микшера, а не доля «пути» между голосами: микшер нормирует строки, поэтому
   изменения сгущаются в середине. Так и пишется в подсказке.
2. **Случайные смеси.** От 2–8 профилей: K = 2–8 наборов весов из Дирихле(α=1) с seed (`u32`),
   генератор `ChaCha8Rng` с ключом из seed и своей формулой выборки (зависит только от алгоритма ChaCha8). Стратегия DP — выбор пользователя,
   кроме `select` (`BATCH_INVALID`).
3. **Сходство с записью.** Необязательно для пачки: источник + регион 1–60 с (согласие на запись
   обязательно, как у клона) → косинус эмбеддинга speaker encoder (CPU) для каждого рендера.
   Лента сортируется по нему. Это подсказка, а не оценка качества. Без энкодера — `ENCODER_MISSING`.
4. **Сохранить из ленты.** «Сохранить снимком» — существующий `vl_save_snapshot` P0 по весам
   из рецепта рендера.
5. **Проект `.svlab`.** ZIP с `manifest.json`, профилями (кроме встроенных) и избранными
   рендерами. Импорт в другой каталог данных: профили, рецепты, теги, избранное.

## Не цели P2

- Пертурбации латентов, карта отличий профилей, постобработка WAV (EQ/высота/темп) — нет
  известного смысла или делается лучше внешним редактором; тянут новый формат рецепта и миграцию.
- Исходные записи в `.svlab` (чужие голоса, большой размер).
- Побитовая воспроизводимость звука: шум латентов в крейте без seed. Воспроизводимы веса и стили.
- Хранение «лент» после перезапуска: рендеры остаются в «Рендерах» с рецептами, подписи ленты —
  состояние UI.

## Решения

- **Пачка** — новая операция P0-воркера `synthBatch`: модель (и энкодер, если нужен) грузится один
  раз; после каждого элемента событие `item{index, durationMs, synthMs, similarity}`, в конце `done`.
  Элементы регистрируются как рендеры после выхода воркера (при любом исходе — готовые остаются).
  Пачка занимает слот синтеза (`JOB_BUSY` для одиночного рендера), отменяется через
  `vl_cancel_job` (готовые элементы возвращаются в ленту, `cancelled: true`); таймаут `300 + 60·N` с. Текст пачки ≤ 300 символов. Стили пачки — во временных
  файлах, в библиотеку попадают только сохранённые снимки.
- Референс сходства вырезается в Rust тем же кодом, что для клона, во временный WAV.
- **`.svlab`**: имена записей архива не превращаются в пути. Читаются только записи из манифеста,
  имена строго `profiles/<64 hex>.json` и `renders/<число>.wav`, через `by_name` с лимитом по
  фактически распакованным байтам: манифест ≤ 1 МБ, профиль ≤ 2 МБ, WAV ≤ 50 МБ, всего ≤ 500 МБ,
  записей ≤ 2000. Профиль: `parse_style`, канонический sha должен совпасть с манифестом; `origin`
  из архива игнорируется (всегда `import`, исходный — в `meta`), `sourceId` из `meta` убирается;
  имя ≤ 200 символов, теги ≤ 20 по ≤ 50. Рендер: параметры через проверки P0, WAV через `hound` (моно, PCM16, 8–48 кГц),
  длительность считается из файла, импортируется с `favorite = 1`. Сначала всё проверяется (профили — в памяти, WAV — во временном каталоге),
  затем применяется; профиль с уже существующим sha пропускается без изменения имени и тегов; сбой IO при применении даёт частичный импорт (повтор безопасен для
  профилей — дедуп по sha; рендеры при повторе дублируются — сказано в документации).
  `assetRevision` другой → предупреждение в отчёте импорта.
- Экспорт собирает список под коротким локом, проверяет лимиты импорта и пишет ZIP потоком в `<путь>.tmp` и переименовывает; правила пути как у экспорта P0.

## Коды ошибок (новые)

`BATCH_INVALID`, `ENCODER_MISSING`, `PROJECT_INVALID`, `PROJECT_TOO_LARGE`.

## Критерий приёмки

Два профиля → интерполяция 5 точек на русской фразе → сохранить t=0.25 снимком → 4 случайных
смеси от трёх профилей с seed 7, повтор с seed 7 даёт те же веса → пачка со сходством к записи
отсортирована → отмена пачки на середине оставляет готовые рендеры → экспорт `.svlab` →
импорт в чистый каталог данных (модель скопирована) → профили, рецепты и избранное на месте,
синтез снимком работает.
