# Voice Lab — дизайн v1 (P0: голоса Supertonic 3 на CPU)

Дата: 2026-11-02
Источник требований: SVL-SPEC-001 «Supertonic Voice Lab» (вставлен пользователем). Этот документ —
его адаптация к Stream Assist: что входит в первый релиз и как это ложится на код.

## Зачем

Локальная студия голоса внутри Stream Assist: импортировать записи голосов, вырезать чистый
фрагмент, сделать из него профиль голоса Supertonic 3 (style JSON), смешать несколько профилей
с весами, послушать результат на одной фразе, сохранить удачные варианты и экспортировать
профиль, рецепт и WAV. Всё на CPU, без CUDA и Python, без сети после скачивания модели.

Профиль голоса — это не модель, а два тензора `style_ttl [1,50,256]` и `style_dp [1,8,16]`
для одной общей модели Supertonic 3.

## Объём v1 = P0 исходной спеки (фазы 0–3)

1. Менеджер модели: скачать Supertonic 3 закреплённой ревизии с Hugging Face по явному
   согласию, проверить SHA-256 каждого файла, хранить LICENSE. Опционально — speaker encoder.
2. Импорт аудио (WAV/MP3/FLAC/OGG/M4A) → рабочая копия WAV mono; оригинал не меняется.
3. Волна, проигрывание, выбор региона (start/end мс), транскрипт, язык. Согласие на запись.
4. Синтез по-русски (и на любом из 31 языков) встроенным или своим профилем, CPU.
5. Клонирование голоса из региона на CPU (`supertonic3-tts`), с прогрессом и отменой.
6. Импорт готовых style JSON v3 с валидацией.
7. Библиотека голосов: имя, теги, происхождение, прослушивание.
8. Микшер 2–N профилей: веса `style_ttl`, `style_dp` = dominant (по умолчанию) | weighted
   (помечен «экспериментально») | select. Undo/redo весов, снимки (неизменяемые рецепты).
9. Превью на одной фразе, история рендеров, сравнение A/B, избранное.
10. Экспорт: чистый style JSON (без metadata), рецепт JSON, WAV.

## Не цели v1 (P1/P2 исходной спеки — позже)

- GPU-тренажёр (Python, WavLM/ECAPA), чекпоинты, resume.
- Латентные пертурбации, «хрипота/эмоция», постобработка WAV (EQ, pitch), проект `.svlab`.
- Слепое A/B, рейтинги по шкалам, автоматические метрики сходства.
- Несколько проектов: в v1 один неявный проект. Журнал задач и таблица регионов — тоже нет
  (регион живёт в форме и в meta профиля).
- Шумодав/VAD как отдельные операции (у клонировщика есть свой `denoise`).
- Feature flag: модуль собирается всегда (решение ассистента, см. «Решения»).

## Анти-цели (провал, даже если «работает»)

- Сломать музыкальную часть: Voice Lab не трогает `db.rs`, `driver.rs`, сервер виджета и их
  инварианты; своя БД и свои потоки.
- UI зависает во время синтеза или клонирования.
- Потеря исходной записи или ранее сохранённого профиля при сбое/отмене.
- Профиль неверной формы или с NaN попадает в библиотеку.
- Клонирование без подтверждённого права на запись.
- Ползунки «эмоция/хрипота», выдаваемые за управление голосом.

## Проверено по исходникам (2026-11-02)

- `supertonic3-tts` **1.3.0** (MIT, crates.io). API:
  `TtsEngine::on_device(onnx_dir, base_path, verbose, Device::Cpu).await`,
  `synthesize_with_style(text, &Style, speed, gain, Some(lang), Some(quality)) -> Vec<f32>`
  (mono, `sample_rate()` = 44100), `clone_voice_with_progress(&Audio, &CloneOptions, cb)`,
  `features::load_wav`, `helper::{VoiceStyleData, StyleComponent, Style}` (`Style { ttl, dp: Array3<f32> }`),
  `save_voice_style`, `validate_voice_quality` (5..=12, по умолчанию 8), `AVAILABLE_LANGS` (31 + `na`).
- В клонировании **нет отмены**: только колбэк прогресса. `synthesize_with_style` объявлен `async`,
  но синхронно считает ONNX внутри (блокирует поток tokio); число потоков ORT не настраивается.
  Поэтому и клон, и синтез идут в одноразовом дочернем процессе (тот же бинарник, скрытый режим),
  отмена = убить процесс. Паника/OOM воркера не задевает музыку, память освобождается.
- Встроенный банк проб-фраз есть только для `en/es/fr/de/it/pt`; для остальных языков без
  транскрипта `VoiceCloner::new` падает («nothing to synthesize»).
- Крейт смешивает стили как нормированную взвешенную сумму (`normalize_rows` после суммы):
  строки `ttl`/`dp` у клонов лежат на единичной сфере.
- Шум латентов — `thread_rng()` без seed: синтез недетерминирован, кэш рендеров бессмыслен.
- `VoiceStyleData`, `save_voice_style`, `load_text_to_speech_on` — в `supertonic3_tts::helper`.
- `CloneOptions`: `language, reference_text, reference_window: Option<(f32,f32)> (секунды),
  init_voice, mix_iterations=40, row_iterations=60, iterations=100, seed=42, speaker_model,
  denoise=0.5, device, voice_quality=8` и др. Для `ru` встроенного банка проб-фраз нет; пустой `reference_text = Some("")` крейт отвергает.
- Зависимости крейта: `ort 2.0.0-rc.12` (скачивает ONNX Runtime при сборке), `cpal` (на Linux
  нужен `alsa-lib`), `ndarray 0.17`, `hound`, `rand 0.8`.
- Модель: HF `Supertone/supertonic-3`, ревизия `3cadd1ee6394adea1bd021217a0e650ede09a323`,
  файлы `onnx/{duration_predictor,text_encoder,vector_estimator,vocoder}.onnx`,
  `onnx/{tts.json,unicode_indexer.json}`, `voice_styles/{F1..F5,M1..M5}.json`, `LICENSE` (~400 МБ).
  Лицензия весов — OpenRAIL-M (запрет обманного использования), код — MIT.
- Speaker encoder: `3dspeaker_speech_eres2net_sv_en_voxceleb_16k.onnx` из релиза
  sherpa-onnx `speaker-recongition-models` (Apache-2.0), опционален, без него клон хуже.
- Не запущено: сборка крейта на этой машине и реальный синтез. Это задача 0 плана (спайк).

## Решения (ассистента)

### Размещение в приложении

- Новая вкладка панели «Голоса» (`src/lib/views/voice/*`), тот же стиль панели и `ru.ts`.
- Rust-модуль `src-tauri/src/voice_lab/`, своё состояние `VoiceLab` в `app.manage`, свои команды
  с префиксом `vl_`. Своя БД `voice-lab.db` (rusqlite, как `db.rs`, миграции через `user_version`).
- Каталог данных: `<app_data_dir>/voice-lab/` —
  `models/supertonic-3/<rev>/`, `models/speaker-encoder/`, `sources/original/<sha256>.<ext>`,
  `sources/work/<id>.wav`, `profiles/<sha256>.json`, `renders/<id>.wav`, `tmp/`.
- Фронт не передаёт путей после импорта: только id. Пути из диалогов открытия/сохранения
  принимаются только в `vl_import_audio`, `vl_import_profile`, `vl_export_*`.

### Модель

- Список файлов и их SHA-256/размеры — константа в коде (снимается в спайке). Скачивание —
  в `tmp`, проверка хэша, атомарный rename. Отдельный HTTP-клиент без общего таймаута 15 с
  (только connect-таймаут и таймаут простоя), иначе 400 МБ не скачать.
- Без модели вкладка показывает только экран установки.
- ONNX грузится только в воркере (см. «Воркер»).

### Аудио

- Декодирование: системный `ffmpeg` с фиксированными аргументами (без shell,
  `-protocol_whitelist file`, на Windows без консольного окна) → WAV mono s16 44100 Гц.
  Нет `ffmpeg` → принимаем только WAV (`features::load_wav` + `resample`), понятная
  ошибка для остальных форматов. Проверка содержимого — по ответу декодера, не по расширению.
- Лимиты: файл ≤ 250 МБ, длительность ≤ 30 мин (ffmpeg с `-t 1801`), регион для клона 1–15 с
  (крейт не режет, а синтезирует регион целиком как одну реплику), прослушивание — фрагмент ≤ 60 с.
  Рабочая копия — WAV mono s16 44100 Гц.
- Волна: бэкенд отдаёт 1000 пиков (max |x| по окнам) — фронт рисует на `<canvas>`.
- Проигрывание: команда отдаёт байты WAV (`tauri::ipc::Response`), фронт делает Blob URL.
  CSP: добавить `media-src 'self' blob:`.

### Профили и валидация

Style JSON принимается, если: файл ≤ 2 МБ; объект с `style_ttl` и `style_dp`; `dims` ровно
`[1,50,256]` и `[1,8,16]`; `type == "float32"`; `data` — вложенный массив этой формы; все
значения конечны. `metadata` игнорируется. Хранится в каноническом виде (сериализация
`Style::to_voice_style_data`, без metadata) под `profiles/<sha256>.json`, где sha256 — от этих
байтов. Одинаковый sha → тот же профиль (дубль не создаётся). Переименование меняет только БД. Встроенные M1–F5 удалить нельзя (`BUILTIN_LOCKED`).

Встроенные M1–M5, F1–F5 регистрируются как профили `origin=builtin` после установки модели.

### Микшер

`p_i = w_i / Σw`; `TTL = Σ p_i·TTL_i` (в f64, результат f32); DP: dominant = DP профиля с
максимальным `p_i` (при равенстве — первый по порядку), weighted = `Σ p_i·DP_i`, select =
DP выбранного участника (он обязан быть среди входов). После суммы каждая строка `TTL`
(50 строк по 256) и, для weighted, `DP` (8 по 16) масштабируется к норме `Σ p_i·‖row_i‖`.
Крейт нормирует строки к 1; мы сохраняем среднюю норму входов — для единичных входов это то же самое. Веса 0–100, конечные, ≥ 0, сумма > 0,
N ≥ 1, профили без повторов. Ошибки: `ZERO_MIX_WEIGHTS`, `MIX_INVALID`. Сырые веса хранятся в
рецепте как введены.

Рецепт (как в исходной спеке §7.3, без `operators`/`ttlStrength`):

```json
{"schemaVersion":1,"kind":"voice-lab-recipe",
 "engine":{"id":"supertonic","version":"3","assetRevision":"3cadd1ee…"},
 "inputs":[{"profileSha256":"…","name":"A","weight":55}],
 "dpStrategy":"dominant","selectedDpProfileSha256":null,"createdAt":"…"}
```

Перед сохранением снимка сверяются `profileSha256` всех входов с файлами
(`PROFILE_HASH_MISMATCH`). Снимок = профиль-результат (`origin=mix`) с рецептом в БД, он
неизменяем. Если результат совпал с существующим профилем (один вход), возвращается он.

Undo/redo — стек состояний весов на фронте (Ctrl+Z / Ctrl+Shift+Z), не персистится.

### Синтез и рендеры

- Параметры: текст 1–1000 символов, язык из `AVAILABLE_LANGS` (по умолчанию `ru`),
  скорость 0.7–1.5, качество 5–12 (по умолчанию 8). Только по кнопке «Сгенерировать».
- Кэша нет: каждое нажатие — новый дубль (синтез недетерминирован, это нужно для A/B).
- Рендер записывает: профиль, текст, язык, скорость, качество, длительность, время синтеза
  (только `tts.call`, без загрузки модели), RTF,
  избранное. Хранится последние 200 неизбранных; старые удаляются вместе с WAV.
- Синтез — в воркере (см. ниже), одновременно один рендер, второй запрос → `JOB_BUSY`.
  Цена — загрузка модели на каждый рендер; замеряется в спайке.

### Воркер, синтез и клонирование

- Скрытый режим бинарника: `stream-assist --vl-worker <request.json>` проверяется в `main.rs`
  до запуска Tauri. Запрос `op: synth|clone`. Воркер синхронный (без tokio): `helper::load_text_to_speech_on(.., Device::Cpu)`,
  для клона `VoiceCloner::new(..).run(cb)`. Пониженный приоритет (Unix `nice(10)`, Windows
  `BELOW_NORMAL_PRIORITY_CLASS | CREATE_NO_WINDOW`). Пишет в stdout JSONL:
  `{"event":"progress",...}`, в конце `{"event":"done",...}` или `{"event":"error","code"}`.
  Строка stdout > 64 КБ — ошибка протокола, не-JSON строки пропускаются, stderr — `null`.
- Воркер завершается сам, когда закрывается его stdin (родитель умер или вышел через
  `app.exit`) — иначе сирота грузил бы CPU минутами.
- Родитель: одна задача синтеза и одна задача клонирования одновременно (`JOB_BUSY`).
  Отмена клона — `kill`; финальный статус пишет только читатель stdout задачи.
  Результат клона валидируется как импорт и только тогда становится профилем
  (`origin=clone`, в meta — источник, регион, транскрипт-хэш, пресет, seed, loss, similarity).
- Состояние задач — в памяти, событие Tauri `vl-job` `{id, kind, status, progress, error,
  profileId}`; статусы `running|completed|failed|cancelled`. Профиль появляется только при
  успехе, поэтому перезапуск ничего не теряет; `tmp/` чистится при старте.
- Клонирование требует: установленную модель, `consent=1` у источника (`NO_CONSENT`), регион
  1–15 с, непустой транскрипт для `ru` (нужен для выравнивания и темпа) и для языков без встроенного
  банка проб-фраз (`TRANSCRIPT_REQUIRED`); `RU_PROBES` (12 фраз) — только дополнительные пробы. Параметры UI:
  имя, язык, транскрипт, итерации (пресеты «быстро» 10/15/25 (voice_quality=5), «стандарт» 20/30/50 (voice_quality=8),
  «точно» 40/60/100 (значения крейта по умолчанию, voice_quality=8)), seed (42), speaker encoder если установлен.

### Экспорт

Сохранить через нативный диалог (`dialog:allow-save`): профиль → чистый style JSON;
снимок (`origin=mix`) → рецепт JSON; рендер → WAV. Бэкенд пишет файл через временный и rename; путь должен
быть абсолютным, родитель — существующий каталог, расширение — ожидаемое.

### Ошибки

Стабильные коды → тексты в `ru.ts`: `MODEL_MISSING`, `MODEL_CHECKSUM_MISMATCH`,
`MODEL_DOWNLOAD_FAILED`, `STYLE_BAD_SCHEMA`, `STYLE_WRONG_SHAPE`, `STYLE_NOT_FINITE`,
`STYLE_TOO_LARGE`, `NO_CONSENT`, `AUDIO_UNSUPPORTED`, `AUDIO_TOO_LARGE`, `AUDIO_TOO_LONG`,
`REGION_INVALID`, `TRANSCRIPT_REQUIRED`, `ZERO_MIX_WEIGHTS`, `MIX_INVALID`,
`PROFILE_HASH_MISMATCH`, `TEXT_INVALID`, `JOB_BUSY`, `WORKER_CRASHED`, `JOB_CANCELLED`,
`NOT_FOUND`, `EXPORT_FAILED`, `IO_FAILED`, `RENDER_INVALID`, `WORKER_FAILED`, `BUILTIN_LOCKED`,
`VOICE_LAB_UNAVAILABLE`. Без трейсбеков в UI.

### Приватность и лицензии

- Записи, транскрипты, профили, WAV — локально. Сеть только для скачивания модели/энкодера.
- В логах нет транскриптов и тензоров.
- На экране установки — ссылка на LICENSE модели и короткое предупреждение OpenRAIL-M:
  не выдавать синтез за речь реального человека без его согласия.

## Критерий приёмки (из исходной спеки §22, урезанный до P0)

Три разрешённые записи A/B/C с русской речью → регионы по ~10 с → три профиля клонированием
(или импортом) → микс 55/30/15 → одна русская фраза → прослушать, подвинуть веса, сохранить
снимок → экспорт `final_voice.json` → импорт в чистый каталог данных (с скопированной `models/`) →
синтез работает.
Без CUDA и Python, после установки модели — без сети.
